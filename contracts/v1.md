# File contract v1

Freeze this interface before feature work. Paths below are examples within a local run directory. Stage functions expose explicit input and output arguments, report errors with a nonzero exit at the command line, and send diagnostics to stderr.

| Producer | Files | Consumer |
| --- | --- | --- |
| Ingest | `baseline.nc`, `target.nc` | Events |
| Events | `events.nc` | Footprints and demo |
| Footprints | `footprints.nc`, `footprints.csv` | Demo |

## Common grid

1. NetCDF with one dimensional coordinates in dimension order `(time, lat, lon)`. `lat` and `lon` are increasing, unique WGS 84 cell centres in degrees north and east. Both axes are regular and have at least two centres. The Milan data use a nominal 0.1° step. Stages preserve and exactly match their grid coordinates, and they never interpolate.
2. `time` is a unique, increasing CF decodable Gregorian coordinate on the UTC day boundary. The canonical date label is `YYYY-MM-DD`. Multiple summers may appear with intentional gaps between years. Missing values appear as NaN for temperature fields.
3. File global metadata include `contract_version = "1"`. Input cubes additionally record the provider or synthetic source, requested bounds and period, and `day_timezone = "UTC"`. The owner of each derived file records the effective scientific parameters used.

## A · Ingest

1. `baseline.nc` contains May through September for each reference year 1991–2020 inclusive. `target.nc` contains May through September 2022. The separate seven day pilot verifies the provider format and is not an input for the full analysis.
2. The data variable is `tx_c(time,lat,lon)`, float32 with units `degC`. Translate CF decoded `t2m` Kelvin with `°C = K − 273.15`. Pin accepted provider aliases from the pilot, including the time coordinate if named `valid_time`. Squeeze only documented, singleton extra dimensions. Reject ambiguous variables and chunk grids.
3. Validate one record per requested date, expected date coverage for each partition, equal spatial grids, and recognized units. Duplicate or missing requested dates are ingest errors for the real case. Valid provider cell masks remain NaN. Sort once and write two separate normalized cubes.

## B · Events

1. Calculate P90 separately per cell and month/day for each of the 92 summer dates. For each baseline year, pool that calendar date and the seven calendar days on either side. Use finite samples and NumPy linear quantiles. A threshold requires at least 405 of the possible 450 values for the Milan baseline. This 90% coverage cutoff is a project quality rule. Align by month/day and actual calendar offsets, so leap years do not shift summer thresholds. Smaller synthetic baselines may use the same proportion of their expected sample counts.
2. Evaluate only 1 June through 31 August, reindex to the complete daily range, and mark every day in a maximal run of at least three observed strict exceedances. Equal to P90 is a break. An absent date, missing temperature or missing threshold breaks the run. The time extent of the reported result is the analysis window, and events touching its boundary can extend outside it.
3. `events.nc` contains `tx_c`, `p90_c`, `excess_c = tx_c − p90_c` as floats in degrees Celsius, and signed byte `heatwave_flag`. Each variable uses all three common dimensions. Flag meanings are `1` qualifies, `0` valid input with no qualifying observed run, and `-1` unknown input. Store these as literal codes without a flag fill value. Signed excess is finite where both inputs are finite, and may be negative.

## C · Footprints

1. Group only flag `1` cells within each day using shared edges. Use increasing latitude and longitude row order for deterministic positive IDs starting at 1 for each day. Order components by their first cell in that scan. Neither a background cell nor an unknown cell joins components. Diagonal contact alone stays separate.
2. `footprints.nc` contains signed integer `footprint_id(time,lat,lon)`: `-1` unknown, `0` background, or the daily positive component identifier. Keep every date and preserve coordinates. Store literal codes without a fill value.
3. `footprints.csv` is UTF‑8 with columns `date,footprint_id,cell_count,area_km2,peak_excess_c` and a row for each positive ID, sorted by date and ID. Keep the header when no component qualifies. Use peak finite `excess_c` for that component.
4. Use nominal edges derived from adjacent centre midpoints with half a grid step at the outer edge. Approximate cell area by `R² × |sin(φnorth) − sin(φsouth)| × |λeast − λwest|`, with radians and `R = 6371.0088 km`. Sum full nominal cell areas per component and compare their daily sum to the area counted directly from flag `1`. The requested coordinates bound grid centres; outer cells can extend up to half a cell farther. A footprint touching a map edge is observed only within this domain.

## Acceptance checks

1. Ingest validates dates, Celsius conversion, grid ordering and equality, and corrupt or incomplete input handling.
2. Events checks known P90 values from a synthetic climatology, two versus three dates, P90 equality, unknown temperature, an absent calendar date, and the summer boundary.
3. Footprints checks a diagonal split, an edge merge, unknown values, positive deterministic IDs, empty output and expected cell area. Aggregate area conservation is the integration check.
4. The committed [synthetic worked example](../notebooks/00_fixture.ipynb) starts from prespecified threshold values and shows the expected event and footprint results. The Events owner adds a separate fixture for the percentile computation.

## Proposed command interfaces

Implement these interfaces in the relevant module PR. The downloader is available now. Run the three planned stage commands from the root after those PRs land:

```bash
mkdir -p runs/milan
python -m heatwave.ingest.normalize --cache-dir data/raw/cds --baseline-out runs/milan/baseline.nc --target-out runs/milan/target.nc
python -m heatwave.events.detect --baseline runs/milan/baseline.nc --target runs/milan/target.nc --out runs/milan/events.nc
python -m heatwave.footprints.summarize --events runs/milan/events.nc --labels-out runs/milan/footprints.nc --summary-out runs/milan/footprints.csv
```

A consumer can substitute the matching synthetic NetCDF from `integration/fixtures/`. The baseline's unique years are inferred from the input; the target must represent one year.
