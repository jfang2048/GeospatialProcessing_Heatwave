# File guide (v1)

| Stage | Reads | Writes |
| --- | --- | --- |
| Ingest | Hourly ARCO data or cached CDS daily files | `baseline.nc` and `target.nc` |
| Events | `baseline.nc` and `target.nc` | `events.nc` |
| Footprints | `events.nc` | `footprints.nc` and `footprints.csv` |

Pass the file paths explicitly to each command. Keep the original inputs read-only and use fresh output paths. Pass the outputs on after the stage exits with status 0. If an input fails a check, the command reports the reason on stderr and exits with a nonzero status. [Run commands](workflow.md)

## Common grid

NetCDF fields use `(time, lat, lon)` and carry `contract_version = "1"`. The `time` axis has unique, increasing Gregorian timestamps at midnight UTC. The spatial axes are regular, increasing WGS 84 cell centres, with at least two centres per axis. The coordinate units are `degrees_north` and `degrees_east`. All stages preserve the input grid. Temperature fields use NaN for missing values. [Milan grid](geography.md)

## A · Ingest

- `baseline.nc` contains May–September of each year from 1991 through 2020. `target.nc` contains May–September 2022. Dates between reference seasons are outside the requested period.
- `tx_c` stores the daily maximum 2 m air temperature as float32 in `degC`. For ARCO, take the maximum of the 24 hourly values in each UTC day, then subtract 273.15 from Kelvin. Cached CDS daily files already contain the maximum.
- Match the dates and grid to the request. Each cube records `source`, `source_doi`, `requested_bounds` (north, west, south, east), `requested_period` and `day_timezone = "UTC"`. The ARCO DOI is `10.24381/ee82e357`. The CDS daily DOI is `10.24381/cds.e9c9c792`.

## B · Events

For each cell and each of the 92 days from 1 June to 31 August, calculate the linear P90 from the same calendar date plus seven days on each side in each reference year. Use finite values. A threshold needs at least 90% of the expected samples, rounded up. For Milan, that is 405 out of 450.

Mark every day in a run of at least three consecutive days strictly above P90 within June–August. A day at or below P90 or with a missing input breaks the run. Fill a missing target date with NaN temperature and excess, keep its P90 where available, and set its flag to `-1`.

| Field in `events.nc` | Meaning |
| --- | --- |
| `tx_c` | Daily maximum temperature in °C |
| `p90_c` | Reference threshold in °C |
| `excess_c` | Signed temperature difference `tx_c − p90_c` in °C |
| `heatwave_flag` | Signed byte. `1` qualifying day, `0` observed without a qualifying run, `-1` unknown |

Write temperature fields as floats and store literal flag codes. The output records `percentile = 90`, `window_days = 15`, `min_run_days = 3`, `minimum_reference_coverage = 0.9` and `baseline_years`.

## C · Footprints

Group flag-`1` cells that share an edge. Start at ID 1 each day and assign IDs by the first cell in row order, scanning longitude across each row and increasing latitude between rows.

- `footprints.nc` keeps every date and stores signed integer `footprint_id` values. Positive IDs identify components, `0` marks background and `-1` marks unknown cells. Store the codes directly and record `connectivity = 4` and `earth_radius_km = 6371.0088`.
- `footprints.csv` is UTF-8. Its columns are `date,footprint_id,cell_count,area_km2,peak_excess_c`, with one row per positive ID, sorted by date and then ID. Each row counts its labelled cells, sums their areas and records their largest finite excess. A run with zero components produces the CSV header.

Place cell edges at adjacent centre midpoints and extend the outside edges by half a grid step. In radians, the area is `R² × |sin(φnorth) − sin(φsouth)| × |λeast − λwest|`, with `R = 6371.0088 km`. Use the full area of each grid cell and round for display only. Area tests use relative tolerance 0.00001 and absolute tolerance 0.000001 km². Dates, flags, IDs and counts match exactly.
