# File contract v1

Status: proposed for team agreement. This contract covers file and CLI handoffs. Each owner chooses the internal Python API and algorithms that satisfy the contract. Use the [geographic specification](geography.md) for the Milan grid, map extents, units and interpretation.

| Producer | Files | Consumer |
| --- | --- | --- |
| Downloader (FJ) | Monthly NetCDF or ZIP files in the local cache | Ingest (FJ), via `--cache-dir` |
| Ingest (FJ) | `baseline.nc`, `target.nc` | Events (YY), via `--baseline` and `--target` |
| Events (YY) | `events.nc` | Footprints (FY), via `--events`, and demo |
| Footprints (FY) | `footprints.nc`, `footprints.csv` | Demo, joined by UTC date and daily positive ID |

**Successful handoff.** The caller supplies explicit, distinct paths in a fresh run directory. The producer treats inputs as read-only, writes all named outputs and exits with status 0. A consumer opens these outputs only after the producer succeeds. The example filenames can be changed without changing the interface.

**Rejected handoff.** An unsupported or missing contract version, incompatible grid, corrupt cache entry, unexpected units, dimension order, data type or undefined flag code is an error at the consuming stage. Return nonzero, identify the offending input and reason on stderr, and leave no completed outputs from that invocation. Unknown cell values and the documented gaps between reference seasons are valid data.

## Common grid

1. NetCDF with one dimensional coordinates in dimension order `(time, lat, lon)`. `lat` and `lon` are increasing, unique WGS 84 cell centres in degrees north and east. Both axes are regular and have at least two centres. The Milan data use a nominal 0.1° step. Stages preserve and exactly match their grid coordinates, and they never interpolate.
2. `time` is a unique, increasing CF decodable Gregorian coordinate on the UTC day boundary. The canonical date label is `YYYY-MM-DD`. Multiple summers may appear with intentional gaps between years. Missing values appear as NaN for temperature fields.
3. Each NetCDF carries the global string attribute `contract_version = "1"`. Ingest cubes also require `source`, `source_doi = "10.24381/cds.e9c9c792"`, `requested_bounds` (north, west, south, east), `requested_period` and `day_timezone = "UTC"`. Coordinate units are `degrees_north` and `degrees_east`. Use the decoded coordinates as the authority for grid placement. The CSV inherits its grid, version and dates from the paired label cube in the same run.

## A · Ingest

1. `baseline.nc` contains May through September for each reference year 1991–2020 inclusive. `target.nc` contains May through September 2022. The separate seven day pilot verifies the provider format and is not an input for the full analysis.
2. The data variable is `tx_c(time,lat,lon)`, float32 with units `degC`. Translate CF decoded `t2m` Kelvin with `°C = K − 273.15`. Pin accepted provider aliases from the pilot, including the time coordinate if named `valid_time`. Squeeze only documented, singleton extra dimensions. Reject ambiguous variables and chunk grids.
3. Validate one record per requested date, expected date coverage for each partition, equal spatial grids, and recognized units. Duplicate or missing requested dates are ingest errors for the real case. Valid provider cell masks remain NaN. Sort once and write two separate normalized cubes.

## B · Events

1. Calculate P90 separately per cell and month/day for each of the 92 summer dates. For each baseline year, pool that calendar date and the seven calendar days on either side. Use finite samples and NumPy linear quantiles. A threshold requires at least 405 of the possible 450 values for the Milan baseline. This 90% coverage cutoff is a project quality rule. Align by month/day and actual calendar offsets, so leap years do not shift summer thresholds.
2. Evaluate only 1 June through 31 August, reindex to the complete daily range, and mark every day in a maximal run of at least three observed strict exceedances. Equality with P90 is a break. An absent target date, missing temperature or missing threshold breaks the run. A run must have at least three qualifying days inside the reporting window, including at either boundary. For a missing target date, preserve its baseline-derived threshold when available and set the temperature and excess to NaN and the flag to -1.
3. `events.nc` contains `tx_c`, `p90_c`, `excess_c = tx_c − p90_c` as floats in degrees Celsius, and signed byte `heatwave_flag`. Each variable uses all three common dimensions. Flag meanings are `1` qualifies, `0` valid input with no qualifying observed run, and `-1` unknown input. Store these as literal codes without a flag fill value. Signed excess is finite where both inputs are finite, and may be negative.

4. Record the attributes `percentile = 90`, `window_days = 15`, `min_run_days = 3`, `minimum_reference_coverage = 0.9` and `baseline_years` identifying the reference years used. The minimum sample count for each cell and month/day is the ceiling of 0.9 × 15 × the number of reference years. Missing samples count against the expected total.

## C · Footprints

1. Group only flag `1` cells within each day using shared edges. Use increasing latitude and longitude row order for deterministic positive IDs starting at 1 for each day. Order components by their first cell in that scan. Neither a background cell nor an unknown cell joins components. Diagonal contact alone stays separate.
2. `footprints.nc` contains signed integer `footprint_id(time,lat,lon)`: `-1` unknown, `0` background, or the daily positive component identifier. Keep every date and preserve coordinates. Store literal codes without a fill value. Record global numeric attributes `connectivity = 4` and `earth_radius_km = 6371.0088` so the label cube identifies the choices used for its paired CSV.
3. `footprints.csv` is UTF‑8 with columns `date,footprint_id,cell_count,area_km2,peak_excess_c` and a row for each positive ID, sorted by date and ID. Keep the header when no component qualifies. Use peak finite `excess_c` for that component.
4. Use nominal edges derived from adjacent centre midpoints with half a grid step at the outer edge. Approximate cell area by `R² × |sin(φnorth) − sin(φsouth)| × |λeast − λwest|`, with radians and `R = 6371.0088 km`. Sum full nominal cell areas per component and compare their daily sum to the area counted directly from flag `1`. The requested coordinates bound grid centres; outer cells can extend up to half a cell farther. A footprint touching a map edge is observed only within this domain.

5. For each date, the positive IDs in the raster must match the CSV IDs exactly. The number of cells with each positive ID must equal its `cell_count`. Compute areas before rounding for presentation. Compare areas in the real-case acceptance tests with relative tolerance 0.00001 and absolute tolerance 0.000001 km². Valid categorical codes, IDs, dates and counts must match exactly.
